# clash-royale-battle-analyzer

クラッシュロワイヤルの対戦履歴を自動で蓄積し、勝率・苦手カード・デッキ相性を分析するローカルツール。

- **バージョン**: v1.10.0
- **現在の状況**: 実装済み・稼働確認済み
- **要件定義書**: [docs/requirements.md](docs/requirements.md)

---

## 何ができるか

- 対戦履歴を自動収集し、ローカルのSQLiteに蓄積する
- 相手デッキに含まれていたカードごとの勝率を集計し、**苦手なカードを特定する**
- 自分の使用デッキで絞り込み、「このデッキだと何に弱いのか」を確認する
- 現在の対戦環境（どのカードが流行しているか）を把握する
- 負けの原因が実力なのかカードレベル差なのかを切り分ける

分析結果はブラウザで開くローカルWebダッシュボードで閲覧する。
複数プレイヤーを登録でき、画面上部で切り替えられる。スマートフォンでも閲覧でき、
ホーム画面に追加するとアプリのように起動する。

---

## 重要な前提

### 過去の履歴は取得できない

公式APIの `battlelog` は**直近の数十戦分しか返さない**（実測で30件、約5日分）。それより古い対戦は取得する手段が存在しない。

したがって本ツールは、**定期的にAPIを叩いて履歴を蓄積していく**方式を取る。分析できるのは運用を開始した日以降の対戦のみで、過去に遡ることはできない。データが貯まるほど分析の精度が上がる。

### APIトークンはIPアドレスに紐づく

トークンは発行時に登録したIPからのアクセスしか許可しない。家庭用回線はIPが変動するため、本ツールは RoyaleAPI の公式プロキシ `proxy.royaleapi.dev` を経由し、トークンには固定IP `45.79.218.79` を登録する方式を既定とする。これにより自宅のIPが変わっても停止しない。

### 収集はPCが起動している間だけ動く

Windowsタスクスケジューラで定期実行するため、PCの電源が入っていない間の対戦は収集されない。収集間隔の間に取得可能件数（実測30件）を超えてプレイした場合は取りこぼしが発生する。取りこぼしの可能性が検知された場合はログに警告を出す。

## セットアップ

### 1. APIトークンを用意する

[docs/setup-api-token.md](docs/setup-api-token.md) の手順に従ってトークンを発行する。
**許可IPには自分のIPではなく `45.79.218.79` を登録すること。**

### 2. 依存パッケージを導入する

```bash
pip install -r requirements.txt
```

### 3. 設定ファイルを作る

`.env.example` を `.env` にコピーし、トークンとプレイヤータグを記入する。

### 4. 設定を診断する

```bash
python scripts/doctor.py
```

トークンの有効性、タグの存在、レベル正規化、バトルログの取得可否をまとめて確認する。
表示されたカードレベルがゲーム内の表示と一致することを、ここで一度確認しておくとよい。

### 5. 初期化と初回収集

```bash
python -m src.collector.collect --init
```

カードマスタの取得、カード画像のダウンロード（約4MB）、初回の対戦収集をまとめて行う。

### 6. 定期収集を登録する

```bash
powershell -ExecutionPolicy Bypass -File scripts/register_task.ps1
```

Windowsタスクスケジューラに1時間おきの収集タスクを登録する。
間隔を変えたい場合は `-IntervalMinutes 30` のように指定する。

### 7. ダッシュボードを開く

```bash
python -m src.web.app
```

ブラウザで `http://127.0.0.1:8730` を開く。

ポートが他のアプリと衝突する場合は、起動時に検知して使用中のプロセス名を表示する。
一時的に変えるなら `--port 8731` のように指定し、恒久的に変えるなら `config.yaml` の
`web.port` を書き換える。

## 使い方

### 画面構成

| 画面 | 内容 |
|---|---|
| サマリー | 全体勝率、勝率の推移、トロフィーの推移、直近の対戦 |
| 苦手カード | 相手カード別の勝率と**ファネルプロット**。**この分析ツールの中心となる画面** |
| 環境 | 相手デッキに現れたカードを出現率順に表示。メタの把握用 |
| 自デッキ | デッキグループ別の成績。表示名を付けられる |
| レベル分析 | レベル差ごとの実測勝率と、**ロジスティック回帰による推定曲線**（95%信頼区間つき） |
| 対戦履歴 | 1戦ごとの記録。両者のデッキを画像で表示。**行をタップすると詳細へ** |
| 対戦の詳細 | タワーの残りHP、カード1枚ごとのレベルと進化、エリクサー漏れ |
| カードの性能 | HP・ダメージ・射程などの性能値。**カード画像をタップすると開く** |

すべての画面に共通して、期間・モード・自デッキの絞り込みが効く。

### 対戦の詳細

対戦履歴の行をタップすると、その試合だけの詳細が開く。

| 項目 | 内容 |
|---|---|
| タワーの残りHP | キング・プリンセスそれぞれ。破壊された塔は「破壊」と表示 |
| カードのレベル | 8枚それぞれのレベル。進化を装備していた場合は進化版の絵柄とバッジで示す |
| エリクサー漏れ | 自分と相手の両方 |
| 平均レベル差 | 自分と相手の平均レベル、および最低〜最高レベル |
| トロフィー変動 | 対戦前のトロフィーと増減 |

キングタワーの残りHPを両者で見比べると、僅差だったのか一方的だったのかが分かる。

公開サイトでは、**対戦履歴に載っている分（既定100件）だけ**詳細ページを用意する。
1試合につき1ファイルを書き出すため、全件を対象にするとファイル数が際限なく増えるため。

### カードの性能

画面のどこでもカード画像をタップすると、そのカードの性能値が開く。苦手カード・環境・
自デッキ・対戦の詳細・サマリーの直近の対戦、いずれからも辿れる。**戻るリンクは開く前に
見ていた画面を指す。**

| 項目 | 内容 |
|---|---|
| HP・ダメージ・秒間ダメージ | レベルを選ぶと切り替わる。カードが複数ユニットを出す場合は、ユニットごとに表示 |
| 基本情報 | コスト・射程・移動速度・展開時間・攻撃対象など、レベルで変わらない値 |
| レベル別の数値 | そのカードに存在する全レベル分の一覧。選択中のレベルの行を強調する |
| 段階のあるカード | 時間経過でダメージが上がるカードは、ゲーム内と同じ `35-120-422` の形で表示する |

#### 性能値はどこから来ているか

**公式APIはカードの性能値を提供していない。** `/cards` が返すのは名前・レアリティ・
コスト・画像・最大レベルだけで、HP・ダメージ・射程は含まれない。

性能値はゲーム本体のデータファイルに入っているが、そこからの抽出は Supercell の
利用規約 §1.1 が禁じている（"obtain any information from the Service or any Supercell
game using any method not expressly permitted by Supercell"）。**本ツールはこの方法を
採らない。**

そのため、内容が **CC BY-SA** で再利用を許諾されており、かつ公開された MediaWiki API で
取得できる [Clash Royale Wiki](https://clashroyale.fandom.com/) を情報源としている。
ライセンス上の義務として、各カードのページに出典・取得日・元ページへのリンクを表示する。

有志が編集する資料のため、値が最新でない可能性がある。画面のリンクから元ページを開いて
照合できるようにしてあるのはそのためである。

#### 数値の計算方法

wiki は性能値を**レベル11基準**で持っている。各レベルの値は

```
そのレベルの値 = 基準値 × 1.1^(レベル - 11)
```

で算出する。これは wiki 自身がレベル別の表を作るのに使っている式と同じなので、
リンク先の表と本ツールの表示は一致する。丸めの都合で ±1 程度ずれることがある。

射程・移動速度・展開時間などはレベルで変わらないため、そのまま「基本情報」に出す。

#### 保守

`--update-card-stats` は122枚を **3リクエスト**（50件ずつのバッチ取得）で取得する。
ゲームのバランス調整後や新カード追加時に実行する。`--update-cards` と `--init` にも
含まれるため、通常はそちらを実行すれば足りる。

wiki の書式が揃っていないカードは自動で取れないことがある。実行時に
「性能値を取得できませんでした」と名前が出るので、そのカードの wiki ページを見て
`src/data/card_stats_manual.json` に追記する。現在は**浪人スサノオ**の1枚だけが対象で、
レベル別の値が変数化されておらず表に直接書かれているため自動取得できない。

なお**鏡**は仕様上そもそも性能値を持たず、**クローン**はレベルで変わる値を持たない。
この2枚は基本情報のみが表示される。

### 対戦数と勝率のファネルプロット

苦手カード画面に、横軸=対戦数・縦軸=勝率でカード画像を並べた散布図を置いている。
この形の図を**ファネルプロット**と呼ぶ。

薄い帯は「偶然で説明できる範囲」で、そのカードの本当の勝率が全体勝率と同じでも、
対戦数が少ないうちは運だけでこの幅に散らばることを示す。幅は

```
全体勝率 ± 1.96 × sqrt(p(1-p) / 対戦数)
```

で、対戦数が増えるほど狭まる。漏斗（funnel）のような形になるのが名前の由来。

**帯の下に出たカードが、偶然では説明しにくい苦手なカード。** 帯の中に居るなら、
勝率が低く見えても対戦数が足りていないだけかもしれない、と読める。表の並び順
（Wilson信頼区間の上限の昇順）と同じ考え方を、図で一目に分かる形にしたもの。

対戦数が1〜2のカードは勝率が0%か100%に張り付いて左端で重なるため、既定では
3戦以上のカードだけを表示する。画面上のプルダウンで変更できる。

カードをクリックすると、そのカードの性能を開く。

### 「苦手カード」の読み方

並び順は**信頼区間の上限が小さい順**にしている。素の勝率で並べると
「1戦して0勝したカード」が勝率0%として上位を独占し、実際の傾向が埋もれるため。
上限は「良く見積もってもこの程度」を意味し、試合数が少ないほど大きくなるので、
証拠の乏しいカードは自動的に後ろへ下がる。

**カード単位の勝率は「そのカードのせいで負けた」ことを意味しない。**
強いデッキに採用されがちなカードは、それ自体の強さと無関係に勝率が低く見える（交絡）。
傾向を掴むための指標として扱うこと。

`config.yaml` の `min_matches`（既定20）に満たないカードは参考値として薄く表示される。

### 複数プレイヤーの追跡

友人など、自分以外のプレイヤーも分析対象にできる。

```bash
python -m src.collector.collect --add-player "#ABC12345"
```

登録すると、以降の定期収集で自動的にそのプレイヤーの対戦も集める。
ダッシュボードのヘッダにプレイヤー切替が現れ、誰の成績でも見られる。

**友人にAPIトークンを用意してもらう必要はない。** クラロワの対戦履歴は公開情報のため、
プレイヤータグさえ分かれば自分のトークンで取得できる。友人に聞くのはタグだけでよい。

集計は常に1人に閉じている。勝率・苦手カード・デッキはプレイヤーごとに独立して算出される。

追跡をやめる場合:

```bash
python -m src.collector.collect --remove-player "#ABC12345"
```

蓄積済みの対戦は削除されない。再度 `--add-player` すれば続きから収集を再開できる。

**注意:** 登録人数を増やすと収集のAPIリクエストが人数分になる。数人であれば
1時間おきの収集でも制限に余裕があるが、大人数を追跡する場合は間隔の見直しが必要になる。

### スマートフォンから見る（PCの状態に依存しない）

分析結果をインターネット上に公開し、**PCがスリープしていても、他の人のスマートフォンからでも
いつでも見られる**ようにできる。サーバーの契約は不要で、費用もかからない。

仕組みは単純で、あらかじめ計算し終えた画面をHTMLとして書き出し、無料のファイル置き場
（Cloudflare Pages）へ上げるだけ。プログラムが動き続ける必要がないため無料で済む。

```bash
python -m src.exporter.publish
```

表示される内容は最後にアップロードした時点のもので、PCを1日1回起動すれば1日1回更新される。
収集はこれまでどおりPCで行う。

公開URLは `https://<プロジェクト名>.pages.dev/<推測困難な32文字>/` の形になり、
**URLを知っている人だけが閲覧できる。**

設定手順は [docs/setup-publish.md](docs/setup-publish.md) を参照。

Safariで開いて「ホーム画面に追加」すると、アイコンから全画面で起動できる。

#### 自宅のWi-Fi内だけでよい場合

`config.yaml` の `web.host` を `0.0.0.0` に変更し、Windowsファイアウォールで
該当ポートを許可すれば、`http://<PCのIP>:8730` で見られる。ただしPCが起動している
必要がある。

### 設定の変更

`config.yaml` で以下を調整できる。

- `min_matches` — 参考値扱いにする試合数のしきい値（既定20）
- `similarity_threshold` — 同一デッキとみなす一致枚数（既定6）
- `target_battle_types` — 集計対象のモード（既定はラダーとランク戦）
- `exclude_draws` — 引き分けを勝率の母数から除くか

> **引き分けについて**
> 現在のクラロワは、延長戦で決着がつかない場合タイブレーカーに入り、
> タワーのHPが減り続けて先に折れた側が負けとなる。両者のタワーHPが
> 完全に一致した場合のみ引き分けが成立するが、実質的にはほぼ起こらない
> （蓄積した153戦で0件）。そのためサマリー画面は通常「勝-敗」だけを表示し、
> **引き分けが1件でも記録されたときだけ「勝-敗-分」に切り替わる**。
> 引き分けは既定では勝率の母数から除かれる（`exclude_draws`）ため、
> 表示されている場合は対戦数と「勝＋敗」が一致しない点に注意する。
- `web.port` — ダッシュボードのポート（既定8730）
- `publish.enabled` / `publish.project_name` — 公開の有効化とプロジェクト名
- `publish.history_limit` — 公開サイトに載せる対戦履歴の件数（既定100）
- `publish.branch` — Cloudflare Pages の本番ブランチ名（既定 production）。wrangler は git リポジトリ内だとローカルのブランチ名を配信先として扱うため、食い違うとプレビュー配信になり公開URLに反映されない
- `level_bucket_step` — レベル差を集計する刻み幅（既定0.25、最小0.125）
- `level_trend_window` — 傾向線をならす範囲。v1.8.0 で傾向線を廃止したため**現在は未使用**

## 運用形態

公開サイトのみで運用する構成を標準とする。**ローカルのダッシュボードは起動しなくてよい。**

```
[PC] 毎日23時: 収集 → 静的サイトの書き出し → アップロード
                                    ↓
[Cloudflare Pages] ← あなたと友人のスマートフォンからいつでも閲覧
```

### ダッシュボードのコードは削除できない

`python -m src.web.app` を起動しない運用でよいが、**Flaskアプリのコード自体は静的サイトの
生成に使われている**（`static_export.py` が内部でテンプレートを描画するため）。
起動しなければ動作もリソース消費も無いので、そのまま残しておくこと。

### 公開サイトでできないこと

| 操作 | 代替手段 |
|---|---|
| 対戦履歴の全件閲覧 | `config.yaml` の `publish.history_limit` を増やす。または一時的にダッシュボードを起動する |

閲覧に必要な機能はすべて公開サイト側に揃っている。書き込みを伴う操作は持たない
（閲覧者が操作できず、所有者だけが使える非対称な機能になるため）。

デッキの呼び名は、コストの高いカード3枚から自動で組み立てている。
例:「メガナイト・インフェルノドラゴン・スケルトンバレル ほか」

公式APIで取得できる内容の一覧。**本ツールが実際に使っているのは一部だけ**なので、
分析軸を増やしたくなったときの参照用として記載する。すべて 2026-09-08 に実測して確認した。

| エンドポイント | 内容 | 本ツールでの利用 |

### プレイヤー情報の中身（38項目）

```

trophies / bestTrophies / legacyTrophyRoadHighScore
```

## 保守について

### 新カードが追加されたら、日本語名の対応表を編集する必要がある

**これは定期的に発生する手作業なので、あらかじめ把握しておくこと。**

公式APIはカード名を**英語でしか返さない**（`Accept-Language` やクエリパラメータによる言語指定にも対応していないことを実測で確認済み）。日本語表示は、本ツールに同梱している対応表ファイルによって実現している。

```
src/data/card_names_ja.json
```

**典拠**: 初期データの日本語名は、クラロワ攻略Wiki（https://wikiwiki.jp/c-r/Cards）のレアリティ別カード一覧に基づく。APIが返すレアリティごとの枚数と一覧の枚数が全レアリティで一致することを検算として用いた。新カードを追記する際も、同サイトを参照するのが確実。

ゲームアップデートで新しいカードが追加されると、そのカードは対応表に存在しないため、**ダッシュボード上で英語名のまま表示される**。集計そのものは正常に動作し続けるので、放置しても分析結果が壊れることはない。ただし画面上の見え方は不揃いになる。

#### 対応手順

1. カードマスタを最新化する

   ```bash
   python -m src.collector.collect --update-cards
   ```

2. 日本語名が未登録のカードを確認する

   ```bash
   python scripts/doctor.py --missing-names
   ```

   未登録のカードIDと英語名が一覧表示される。

3. `src/data/card_names_ja.json` に、該当するカードIDのエントリを追記する

   ```json
   {
     "26000000": { "en": "Knight", "ja": "ナイト" },
     "26000123": { "en": "New Card Name", "ja": "新カードの日本語名" }
   }
   ```

   - **キーはカードID**（英語名ではない）。カードIDは変更されないため、対応表の壊れにくいキーとなる
   - `en` は編集時の目印として併記しているだけで、処理には使用しない
   - ファイルは **UTF-8** で保存すること

4. 反映する

   ```bash
   python -m src.collector.collect --reload-names
   ```

   ダッシュボードを再読み込みすると日本語名が表示される。

#### 仕様上の制限

本バージョンでは、以下は**実装しない**方針としている。

- ダッシュボード画面上から日本語名を編集する機能
- 「エレウィズ」「ゴブジャイ」などの略称によるカード検索

日本語名の追加は、上記のとおりJSONファイルを直接編集して対応する。

### 初回セットアップ時の名称確認を推奨する

同梱の対応表は目視で作成しているため、訳語の揺れなどの誤りが含まれている可能性がある。初回セットアップ時に一度、次のコマンドで全カードの一覧を出力し、ゲーム内の表記と突き合わせておくことを推奨する。

```bash
python scripts/doctor.py --list-cards
```

### カードレベルの検証

APIが返すカードレベルはレアリティごとに基準が異なるため、本ツールはゲーム内表示と一致するよう正規化している。ゲーム最大レベルはカードマスタから自動導出するため、アップデートで上限が引き上げられても追随する。

変換が正しいことを実データで確認するため、初回に次のコマンドで自分のカードのレベルを表示し、ゲーム内の表示と一致するか確認すること。

```bash
python scripts/doctor.py --check-levels
```
