# 使用方法

以下は 2026-11-15 に実行して動作を確認した: `python -m src.collector.collect --help`、`python -m src.web.app --help`、`python -m src.exporter.publish --help`、`python -m src.exporter.static_export --help`、`python scripts/backup.py --help`、`python -m tests.check_baseline`。
それ以外（収集、診断、公開、タスクの登録、カードの更新など）は、API・データベース・公開サイト・タスクスケジューラへの書き込みや通信を伴うため実行しておらず「未検証」としている。

## 前提条件

- Windows（定期収集はタスクスケジューラを使う）。
- Python。TODO(要確認): 必要な Python のバージョンは記録がない。
- Supercell の開発者アカウントと API トークン、自分のプレイヤータグ。
- 公開サイトを使う場合は、Cloudflare のアカウントと Node.js（`npx` で wrangler を使う）。

## インストール

### 1. APIトークンを用意する

[APIトークンの取得（詳細）](#apiトークンの取得詳細) の手順に従ってトークンを発行する。
**許可IPには自分のIPではなく `45.79.218.79` を登録すること。**

### 2. 依存パッケージを導入する

```bash
pip install -r requirements.txt
```

### 3. 設定ファイルを作る

`.env.example` を `.env` にコピーし、トークンとプレイヤータグを記入する。

### 4. 設定を診断する

```bash
python scripts/doctor.py
```

トークンの有効性、タグの存在、レベル正規化、バトルログの取得可否をまとめて確認する。
表示されたカードレベルがゲーム内の表示と一致することを、ここで一度確認しておくとよい。

### 5. 初期化と初回収集

```bash
python -m src.collector.collect --init
```

カードマスタの取得、カード画像のダウンロード（約4MB）、初回の対戦収集をまとめて行う。

### 6. 定期収集を登録する

```bash
powershell -ExecutionPolicy Bypass -File scripts/register_task.ps1 -DailyAt 23:00
```

Windowsタスクスケジューラに、毎日23時に1回収集するタスクを登録する。
1日1回の収集では、その日に30戦以上プレイすると取りこぼすため、対戦数が多い場合は
`-DailyAt` を外して間隔指定で登録する（既定は60分おき。`-IntervalMinutes 30` のように変更できる）。
公開サイトを使う場合は、`-Publish -DailyAt 23:00` で登録し直す（後述の「運用形態」を参照）。

### 7. ダッシュボードを開く

```bash
python -m src.web.app
```

ブラウザで `http://127.0.0.1:8730` を開く。

ポートが他のアプリと衝突する場合は、起動時に検知して使用中のプロセス名を表示する。
一時的に変えるなら `--port 8731` のように指定し、恒久的に変えるなら `config.yaml` の
`web.port` を書き換える。

### APIトークンの取得（詳細）

クラッシュロワイヤル公式APIのトークンを発行し、本ツールから使えるようにするまでの手順。所要時間はおよそ10分。


#### 0. この作業で何をするのか

やることは3つだけ。

1. Supercellの開発者サイトでアカウントを作る
2. **許可IPに `45.79.218.79` を指定して**トークンを発行する
3. トークンとプレイヤータグを `.env` に書く

**手順2の「許可IP」の指定がこの作業の要点**であり、ここを間違えると後で必ず動かなくなる。理由は次節のとおり。


#### 1. なぜ `45.79.218.79` を登録するのか

Supercellのトークンは、**発行時に登録したIPアドレスからのアクセスしか受け付けない**。登録外のIPから叩くと `403` で拒否される。

自宅の回線はグローバルIPが変動しうる。ルーターの再起動や回線側の都合でIPが変わると、その瞬間からツールが全滅し、トークンを発行し直すまで復旧しない。

そこで本ツールは、RoyaleAPIが公開している中継サーバー `proxy.royaleapi.dev` を経由してAPIを呼ぶ。Supercell側から見たアクセス元は常にこの中継サーバーのIP `45.79.218.79` になるため、**自宅のIPが何回変わっても影響を受けない。**

```
[自宅PC]  --->  [proxy.royaleapi.dev]  --->  [Supercell API]
 IPは変動          IP: 45.79.218.79            ここに見えるIPは常に固定
```

したがって、トークンに登録すべきIPは**自分のIPではなく、中継サーバーのIP**である。ここを自分のIPにしてしまうと、プロキシ経由のアクセスが弾かれる。


#### 2. 開発者アカウントを作る

1. ブラウザで **https://developer.clashroyale.com** を開く
2. 右上の **Login** から、アカウント作成の導線に進む（`Sign up` / `Create account` などの表記）
3. メールアドレスとパスワードを入力して登録する

> ゲーム内のSupercell IDとは**別のアカウント**である。ゲームのログイン情報は使えないため、新規に作成する必要がある。

4. 登録したメールアドレス宛に確認メールが届くので、本文中のリンクを開いて認証を完了する

   届かない場合は迷惑メールフォルダを確認する。

5. 認証後、あらためてログインする


#### 3. トークンを発行する

1. ログイン後、画面上部の **My Account** を開く
2. **Create New Key**（新しいキーを作成）を選ぶ
3. 次の3項目を入力する

   | 項目 | 入力する内容 |
   |---|---|
   | **Key Name** | `battle-analyzer`（半角英数字。任意の名前でよい） |
   | **Description** | `Personal battle log analyzer`（任意の説明） |
   | **Allowed IP Addresses** | **`45.79.218.79`** |

   **Allowed IP Addresses には必ず `45.79.218.79` を入力する。** 自分のIPアドレスではない。画面に自分のIPが初期値として表示されている場合は、消して入力し直す。

4. **Create Key** を押す
5. 発行されたトークンが画面に表示される

トークンは `eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...` のように始まる、**数百文字の非常に長い文字列**である。

6. トークン全体を選択してコピーする

   途中で切れていないか注意する。長いため、選択漏れが起きやすい。

> 発行済みトークンは My Account からいつでも再表示できる。控え忘れても作り直す必要はない。


#### 4. プレイヤータグを調べる

1. クラッシュロワイヤルを起動する
2. 左上の自分の名前をタップしてプロフィール画面を開く
3. 名前の下に表示されている `#` で始まる文字列がプレイヤータグ

##### タグを書き写すときの注意

クラロワのタグに使われる文字は、以下に限られる。

```
0 2 8 9 P Y L Q G R J C U V
```

**アルファベットの `O`（オー）は使われない。`0`（ゼロ）である。** 同様に `I`（アイ）や `1` も使われない。読み間違えると `404` エラーになるので、迷ったらゼロと解釈する。


#### 5. `.env` に設定する

プロジェクト直下の `.env.example` を `.env` という名前でコピーし、次のように記入する。

```
CR_API_TOKEN=eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...
CR_PLAYER_TAG=#ABC12345
CR_USE_PROXY=true
```

##### 記入時の注意

- **トークンは改行を入れず1行で書く。** エディタの折り返し表示は問題ないが、実際に改行を入れてはいけない
- トークンをクォートで囲む必要はない
- `=` の前後に空白を入れない
- プレイヤータグは `#` を付けたまま書く（URLエンコードはツール側で行う）
- ファイルは **UTF-8** で保存する


#### 6. 動作確認

##### ツールの診断コマンドを使う場合

```bash
python scripts/doctor.py
```

トークンの有効性、プレイヤータグの存在、プロキシ経由の疎通をまとめて確認する。

##### コマンドで直接確認する場合

PowerShellで次を実行する。`ここにトークン` と `ABC12345` は自分の値に置き換える。

```bash
$t = "ここにトークン"; Invoke-RestMethod -Uri "https://proxy.royaleapi.dev/v1/players/%23ABC12345" -Headers @{Authorization="Bearer $t"} | Select-Object name, tag, trophies
```

自分の名前・タグ・トロフィー数が表示されれば成功。


#### 7. うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| `403` / `accessDenied.invalidIp` | 許可IPの指定が誤っている。自分のIPを登録してしまった場合が最も多い | My Account でキーを削除し、`45.79.218.79` を指定して作り直す |
| `403` / `accessDenied` | トークンが誤っている。コピー時に末尾が欠けている場合が多い | トークンを再表示し、全体をコピーし直す |
| `404` / `notFound` | プレイヤータグが誤っている | `O` と `0` の取り違えを疑う。ゲーム内の表示と1文字ずつ照合する |
| `503` | Supercell側のメンテナンス中 | 時間をおいて再試行する。ゲーム自体も遊べない状態のはず |
| 何も返らない・タイムアウト | プロキシへの通信が遮断されている | ファイアウォールやVPNの設定を確認する |

##### 直接アクセスに切り替えたい場合

プロキシを使わず、自分のIPを登録して直接叩くこともできる。

1. https://api.ipify.org で自分のグローバルIPを確認する
2. そのIPを許可IPに指定してキーを作り直す
3. `.env` の `CR_USE_PROXY` を `false` にする

ただしIPが変わるたびにキーの作り直しが必要になるため、常用は推奨しない。


#### 8. トークンの取り扱い

トークンは**パスワードと同等の秘密情報**として扱う。

- `.env` は `.gitignore` に登録済みであり、Gitには含まれない
- スクリーンショットや画面共有にトークンが写り込まないよう注意する
- 質問などで設定内容を他人に見せる際は、トークン部分を必ず伏せる
- 漏洩が疑われる場合は、My Account から該当キーを削除して作り直す。削除すれば古いトークンは即座に無効になる

なお、このトークンで可能なのは**公開情報の読み取りのみ**である。ゲームアカウントの操作や課金は一切できない。とはいえ不必要に共有しないこと。

## 基本的な使い方

### 画面構成

| 画面 | 内容 |
|---|---|
| サマリー | 全体勝率、勝率の推移、トロフィーの推移 |
| 相手カード | 相手カード別の勝率。**この分析ツールの中心となる画面**。画面の先頭に**「勝率 × 対戦数」のマトリクス**（縦は上ほど苦手、横は右ほどよく当たる）を置き、全カードを画像のまま一覧できる。続く表は最初はデルタの小さい順（苦手な順）で、**見出しを押すと対戦数・勝率・デルタ・出現率で並べ替えられる** |
| 自デッキ | デッキグループ別の成績。表示するのは最後に使った構成で、構成ごとの内訳も出す（既定は閉じた状態）。進化・ヒーローは、その構成を最後に使った対戦の装備に合わせた画像で示す |
| 対戦履歴 | 1戦ごとの記録。両者のデッキを画像で表示（進化・ヒーローはその絵柄で示す）。**行をタップすると詳細へ**。相手カードで絞り込める（よく当たる順に並んだ画像から選ぶか、名前で探す） |
| レベル分析 | レベル差ごとの実測勝率と、**ロジスティック回帰による推定曲線**（95%信頼区間つき） |
| カード育成 | **カードごとの育成状況**。レベル・**今の所持枚数だけで到達できるレベル**・所持枚数・次のレベルに必要な枚数・カードマスタリーの段階（**いまの段階 / いま解放されている上限 / そのカードの最大** の3つで示す。タスクのセットはLv7/10/14で順に解放される）を一覧にする。**表の見出しを押すと、その列で並べ替えられる**（もう一度押すと逆順）。**カード画像をタップすると性能のページへ** |
| 呪文 | 呪文とレベルを選ぶと、前後2レベルのユニット・建物のうち倒せるものを一覧にする |
| 対戦の詳細 | タワーの残りHP、カード1枚ごとのレベルと進化、エリクサー漏れ |
| カードの性能 | HP・ダメージ・射程などの性能値。**カード画像をタップすると開く** |

すべての画面に共通して、期間・モード・自デッキの絞り込みが効く。

## ユースケース別の手順

### 対戦の詳細を見る

対戦履歴の行をタップすると、その試合だけの詳細が開く。

| 項目 | 内容 |
|---|---|
| タワーの残りHP | キング・プリンセスそれぞれ。破壊された塔は「破壊」と表示 |
| カードのレベル | 8枚それぞれのレベル。進化・ヒーローを装備していた場合は、それぞれの絵柄とバッジで示す |
| エリクサー漏れ | 自分と相手の両方 |
| 平均レベル差 | 自分と相手の平均レベル、および最低〜最高レベル |
| トロフィー変動 | 対戦前のトロフィーと増減 |

キングタワーの残りHPを両者で見比べると、僅差だったのか一方的だったのかが分かる。

公開サイトでは、**対戦履歴に載っている分（既定100件）だけ**詳細ページを用意する。
1試合につき1ファイルを書き出すため、全件を対象にするとファイル数が際限なく増えるため。

### カードの性能を見る

画面のどこでもカード画像をタップすると、そのカードの性能値が開く。相手カード・
自デッキ・対戦の詳細、いずれからも辿れる。**戻るリンクは開く前に
見ていた画面を指す。**

| 項目 | 内容 |
|---|---|
| HP・ダメージ・秒間ダメージ | レベルを選ぶと切り替わる。カードが複数ユニットを出す場合は、ユニットごとに表示 |
| 基本情報 | コスト・射程・移動速度・展開時間・攻撃対象など、レベルで変わらない値 |
| レベル別の数値 | そのカードに存在する全レベル分の一覧。選択中のレベルの行を強調する |
| 段階のあるカード | 時間経過でダメージが上がるカードは、ゲーム内と同じ `35-120-422` の形で表示する |

性能値の出典と計算方法は [architecture.md](architecture.md#カードの性能値の出典と計算)、性能値の更新の手順は [development.md](development.md#カードの性能値の保守) を参照。

### 呪文で倒せるユニットを見る

ナビの「呪文」タブで、呪文とレベルを選ぶと、その呪文で倒せるユニットと建物を一覧にする。
呪文のレベルを L とすると、**レベル L−2〜L+2 のユニット**と比べる。たとえば Lv.13 の
ファイアボールなら、Lv.11〜15 のユニットそれぞれについて倒せるかを示す。

| 記号 | 意味 |
|---|---|
| ○ | 呪文の合計ダメージがHP以上で倒せる（HPがちょうど0でも倒れるため「以下」で判定） |
| × | 倒せない。数字は残るHP |
| 盾 | シールドに吸収されて本体は無傷 |
| — | そのユニットにそのレベルが存在しない（ウルトラレアの8以下など） |

判定の前提は次のとおり。

- **複数回当たる呪文は合計で判定する**（矢の雨は×3、ポイズンは×8）。持続して当たる
  呪文（ポイズン・アースクエイク・ゴブリンの呪い）は、範囲内に留まり続けた場合の合計
- **シールドを割ったダメージの余りは本体に届かない**。1回だけ当たる呪文では、
  盾の戦士・ダークプリンス・見習い親衛隊は倒せない
- ローリングウッド・アースクエイク・ローリングバーバリアンは**地上にしか当たらない**ため、
  空中ユニットは対象から外す
- アースクエイクは建物に別の大きなダメージが入るため、建物にはそちらで判定する
- ボイドは命中した敵の数でダメージが変わるので、画面で命中数を選ぶ
- 派生ユニット（ゴーレマイト・ラヴァパップ・墓石から出るスケルトンなど）も判定に含める

数値はカードの性能と同じ式（レベル11基準 × 1.1^(レベル−11)）で求めるため、丸めの都合で
ゲーム内と ±1 ずれることがある。境目ぎりぎりの判定は目安として扱うこと。

選んだ呪文とレベルはURLの末尾（`#spell=28000000&lv=13`）に残るので、同じ条件のまま
共有・再訪できる。

呪文の定義を足す・直す手順は [development.md](development.md#呪文の定義を足す直すには) を参照。

### 「苦手カード」を読む

並び順は**信頼区間の上限が小さい順**にしている。素の勝率で並べると
「1戦して0勝したカード」が勝率0%として上位を独占し、実際の傾向が埋もれるため。
上限は「良く見積もってもこの程度」を意味し、試合数が少ないほど大きくなるので、
証拠の乏しいカードは自動的に後ろへ下がる。

**カード単位の勝率は「そのカードのせいで負けた」ことを意味しない。**
強いデッキに採用されがちなカードは、それ自体の強さと無関係に勝率が低く見える（交絡）。
傾向を掴むための指標として扱うこと。

`config.yaml` の `min_matches`（既定20）に満たないカードは参考値として薄く表示される。

### 複数のプレイヤーを追跡する

友人など、自分以外のプレイヤーも分析対象にできる。

```bash
python -m src.collector.collect --add-player "#ABC12345"
```

登録すると、以降の定期収集で自動的にそのプレイヤーの対戦も集める。
ダッシュボードのヘッダにプレイヤー切替が現れ、誰の成績でも見られる。

**友人にAPIトークンを用意してもらう必要はない。** クラロワの対戦履歴は公開情報のため、
プレイヤータグさえ分かれば自分のトークンで取得できる。友人に聞くのはタグだけでよい。

集計は常に1人に閉じている。勝率・苦手カード・デッキはプレイヤーごとに独立して算出される。

追跡をやめる場合:

```bash
python -m src.collector.collect --remove-player "#ABC12345"
```

蓄積済みの対戦は削除されない。再度 `--add-player` すれば続きから収集を再開できる。

**注意:** 登録人数を増やすと収集のAPIリクエストが人数分になる。数人であれば
収集間隔を短くしても制限に余裕があるが、大人数を追跡する場合は間隔の見直しが必要になる。

### スマートフォンから見る（PCの状態に依存しない）

分析結果をインターネット上に公開し、**PCがスリープしていても、他の人のスマートフォンからでも
いつでも見られる**ようにできる。サーバーの契約は不要で、費用もかからない。

仕組みは単純で、あらかじめ計算し終えた画面をHTMLとして書き出し、無料のファイル置き場
（Cloudflare Pages）へ上げるだけ。プログラムが動き続ける必要がないため無料で済む。

```bash
python -m src.exporter.publish
```

表示される内容は最後にアップロードした時点のもので、PCを1日1回起動すれば1日1回更新される。
収集はこれまでどおりPCで行う。

公開URLは `https://<プロジェクト名>.pages.dev/<推測困難な32文字>/` の形になり、
**URLを知っている人だけが閲覧できる。**

設定手順は [公開の設定（詳細）](#公開の設定詳細) を参照。

Safariで開いて「ホーム画面に追加」すると、アイコンから全画面で起動できる。

#### 自宅のWi-Fi内だけでよい場合

`config.yaml` の `web.host` を `0.0.0.0` に変更し、Windowsファイアウォールで
該当ポートを許可すれば、`http://<PCのIP>:8730` で見られる。ただしPCが起動している
必要がある。

### 公開の設定（詳細）

分析結果をインターネット上に置き、PCがスリープしていてもスマートフォンから
見られるようにする手順。所要時間はおよそ15分。


#### 0. 仕組み

サーバーは借りない。**あらかじめ計算し終えた画面をファイルとして書き出し、
無料のファイル置き場に上げるだけ**の構成にする。

```
[あなたのPC]
  1. 対戦を収集する
  2. 全画面をHTMLとして書き出す
  3. アップロードする
        |
        v
[Cloudflare Pages]  ← 無料。24時間つながる
        |
        v
[あなたと友人のスマートフォン]  ← いつでも見られる
```

表示される内容は**最後にアップロードした時点のもの**になる。PCを1日1回起動すれば
1日1回更新される。プログラムが動き続ける必要はないので、費用はかからない。

##### URLについて

公開先は次の形になる。

```
https://<プロジェクト名>.pages.dev/<推測困難な32文字>/
```

後半の32文字はランダムに生成される。**このURLを知っている人だけが閲覧できる。**
検索エンジンにも載らないよう設定している。URLを知らせる相手は選ぶこと。


#### 1. Cloudflareのアカウントを作る

1. https://dash.cloudflare.com/sign-up を開く
2. メールアドレスとパスワードを入力して登録する
3. **確認メールのリンクを必ず開く**

クレジットカードの登録は不要。ドメインの購入も不要。

> **手順3を飛ばすと、後のアップロードで失敗する。**
> メール未確認のままだと、ログインには成功するのにプロジェクト作成だけが
> 次のエラーで止まる。原因が分かりにくいので、先に済ませておくこと。
>
> ```
> Your user email must been verified [code: 8000077]
> ```
>
> メールが見当たらない場合は迷惑メールフォルダを確認する。
> それでも無ければ、https://dash.cloudflare.com にログインすると画面上部に
> 確認を促す帯が出るので、そこから再送できる。確認後、同じコマンドを
> 再実行すればよい（`wrangler login` のやり直しは不要）。


#### 2. アップロード用ツールにログインする

コマンドプロンプトやPowerShellで、プロジェクトのフォルダに移動して次を実行する。

```bash
npx --yes wrangler@latest login
```

ブラウザが開くので、Cloudflareへのアクセスを許可する。**この操作は最初の1回だけ。**

> `npx` は Node.js に付属するコマンド。すでにインストール済みであることを確認済み。


#### 3. 静的サイトを書き出す

```bash
python -m src.exporter.static_export
```

`dist/` フォルダの下に、推測困難な名前のフォルダが作られる。この名前が公開URLの
一部になる。**この名前は控えておく必要はない。** 後からいつでも確認できる。


#### 4. 最初のアップロード

プロジェクト名を決めて実行する（英小文字・数字・ハイフンのみ）。

```bash
npx --yes wrangler@latest pages deploy dist --project-name cr-analyzer
```

初回はプロジェクトの作成確認が出るので、指示に従って進める。
完了すると `https://cr-analyzer.pages.dev` のようなURLが表示される。

**実際に開くURLは、この後ろに推測困難な文字列を付けたもの**になる。
次のコマンドで正確なURLを確認できる。

```bash
python -m src.exporter.publish --skip-collect --skip-upload
```

出力の最後に公開URLが表示される。


#### 5. 自動化の設定

`config.yaml` を開き、`publish` の項目を書き換える。

```yaml
publish:
  enabled: true
  project_name: "cr-analyzer"
```

これで、収集から公開までを一括で実行できるようになる。

```bash
python -m src.exporter.publish
```

##### 定期実行を公開込みに切り替える

これまでは収集だけを定期実行していた。公開まで行うよう登録し直す。

```bash
powershell -ExecutionPolicy Bypass -File scripts/register_task.ps1 -Publish
```

以降、収集のたびに自動でアップロードされる。


#### 6. 友人へURLを渡す

確認したURLをそのまま伝える。友人側に必要な準備は何もない。
ブラウザで開くだけで、あなたと同じ画面が見られる。

Safariで開いて「ホーム画面に追加」すると、アプリのように起動できる。


#### 運用について

##### 更新のタイミング

アップロードは、あなたのPCで定期収集が動いたときに行われる。
PCがスリープ・電源オフの間は更新されないが、**閲覧はいつでもできる**。

##### 通信量

1画面あたり300〜400KB程度。カード画像は表示サイズに合わせて縮小し、
WebP形式へ変換しているため、スマートフォンの通信でも負担にならない。

##### 費用

Cloudflare Pages の無料枠に十分収まる。サイト全体で10MB以下、
1日のアップロード回数も無料枠（500回/月）を大きく下回る。

##### URLを変えたいとき

URLが第三者に知られてしまった場合は、次のコマンドで新しいURLを発行できる。

```bash
python -m src.exporter.static_export --rotate-secret --clean
python -m src.exporter.publish --skip-collect
```

古いURLは、次回のアップロードで削除される。


#### うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| `npx` が見つからない | Node.js が入っていない | https://nodejs.org からインストールする |
| ログイン画面が開かない | ブラウザの既定設定 | 表示されたURLを手動でブラウザに貼り付ける |
| `email must been verified` | メールアドレス未確認 | 確認メールのリンクを開いてから再実行する |
| `Project not found` | プロジェクト名の誤り | Cloudflareの管理画面で名前を確認する |
| 画面が古いまま | アップロードされていない | `data/logs/collect.log` を確認する |
| 404 が出る | URLの推測困難な部分が抜けている | `publish --skip-collect --skip-upload` でURLを確認する |
