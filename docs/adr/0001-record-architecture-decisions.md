# 0001. ADR で設計判断を記録する

- ステータス: Accepted
- 日付: 2026-11-15

## 背景（Context）

設計判断は、旧要件定義書の「確定した設計判断の一覧」に表でまとめられていたが、理由と代替案は本文の各所に分散していた。

## 決定内容（Decision）

重要な設計判断を、`docs/adr/` に ADR として1判断1ファイルで記録する。

## 理由と検討した代替案（Consequences / Alternatives）

- 判断の背景と理由が残り、後から変更するときの判断材料になる。
- 代替案: 要件定義書の表に書き続ける → 判断の単位で理由・置き換えを追えないため採用しない。
